# Website implementation

Implemented from `context.md` and `codex-prompt.md` on 5 October 2026.

## Content and structure

- All existing pages updated, with all seven existing service slugs retained.
- Five service entries added: kitchens, orangeries, steel erection, restoration/renovation and demolition. All 12 use `src/data/services.json` and the existing dynamic route.
- Shared hero, service cards, FAQs and optimised image components use the existing QB identity and layout patterns.
- Projects is an honest interim enquiry page, without invented case studies. It is noindex and excluded from the sitemap.
- Privacy Policy is linked in the footer and contact page. The full policy is a visibly labelled, noindex review draft, with highlighted confirmation points. Edit the implementation copy in `src/content/privacy-policy.md`.
- The nonfunctional contact form has been replaced by the brief's phone/email fallback. No new form provider or tracking service was introduced.
- Map embedding, cdnjs and hardcoded GitHub asset requests were removed. Images, styling and the Commissioner font are served locally; the font licence is included in `src/assets/fonts/OFL.txt`.
- Responsive WebP image variants are generated by Astro. Decorative hero images have empty alt text; informative images have factual descriptions.
- `src/styles/global.css` is the single imported stylesheet. The obsolete public copy was removed.

## SEO and deployment

Titles and descriptions are page-specific. Pages have one H1, canonical URLs, Open Graph data, valid Organization JSON-LD and Service JSON-LD where appropriate. Local links use Astro's base path. The existing sitemap integration excludes noindex content; the robots endpoint points at the sitemap index.

`SITE_BASE=/qb-building-solutions` supports a subpath preview. `PUBLIC_SITE_PREVIEW=true` marks preview pages noindex, disallows crawling in robots.txt and omits preview sitemap entries. The production domain remains `https://qbbuildingsolutions.com`; preview prefixes are excluded from canonicals.

The existing GitHub Pages workflow now runs `check:publication` before building and `check:site` before uploading. Publication is deliberately blocked while the privacy policy is a draft or contains `[CONFIRM:` markers. After the actual details are verified and editorial markers resolved, set its frontmatter to `status: approved`. This is not a substitute for business review. Local `npm run build` remains available to inspect the complete site. No commit or deployment was made.

## Verification

- Production build: all 19 HTML pages generated successfully, plus robots.txt and sitemap.
- `npm run check:site`: checks page count, service routes, titles/descriptions, H1s, canonical/OG data, JSON-LD, local links/assets, fragment links, noindex rules and sitemap/robots output.
- Subpath preview build and the same output checks passed with `SITE_BASE=/qb-building-solutions` and `PUBLIC_SITE_PREVIEW=true`.
- Browser checks: all 19 pages at 320px; representative pages at 390px, 768px and 1280px. No horizontal page overflow or broken loaded images found. Reviewed hero, cards, scope lists, process steps, contact information, policy tables and footer.
- Mobile menu expands, closes with Escape and returns focus; native FAQ disclosures expand correctly. No console errors observed during the production review.
- `check:publication` fails as intended while the policy is a draft. Do not upload the local build as an approved release yet.

On a restricted Windows environment, `ASTRO_TELEMETRY_DISABLED=1` avoids Astro writing telemetry configuration outside the workspace. The build also required normal filesystem access for the installed toolchain; it passed with that access.
